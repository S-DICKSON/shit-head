# Milestone v2.1: Quality & Testing

**Status:** SHIPPED 2026-02-22
**Phases:** 24-25
**Total Plans:** 9

## Overview

Quality-focused milestone adding Playwright E2E testing infrastructure and a bot player for solo play and manual testing. Extends the v2.0 codebase with developer tooling and QA capabilities without changing core gameplay.

## Phases

### Phase 24: Playwright Responsive E2E Testing

**Goal**: Add Playwright E2E testing to validate the UI works across mobile, tablet, laptop, desktop, and Discord iframe viewport sizes. Tests cover home screen, lobby screen, prepare phase (card swaps), and active in-game play.
**Depends on**: None (first phase of v2.1)
**Plans**: 4 plans

Plans:

- [x] 24-01: Scaffold packages/e2e with Playwright config and Page Object Models
- [x] 24-02: Home screen and lobby screen E2E tests (real WS)
- [x] 24-03: Swap phase and game screen E2E tests (WS mocked) + CI integration
- [x] 24-04: Gap closure: Switch mobile projects from WebKit to Chromium, remove skip guards

**Details:**
- 6-viewport Playwright config: mobile-375, mobile-390, tablet-768, laptop-1280, desktop-1920, discord-iframe-460
- 4 Page Object Models: LandingPage, LobbyPage, SwapPhasePage, GamePage
- 150 tests total (25 scenarios x 6 viewports), 0 skipped
- All projects use Chromium with explicit viewport + hasTouch + isMobile for mobile simulation
- CI pipeline updated with Playwright install, test run, and HTML report artifact upload
- WS mocking via routeWebSocket for swap phase and game screen tests
- Real WebSocket connections for home and lobby screen tests

**Verified:** 11/11 must-haves (2026-02-22)

### Phase 25: Bot Player

**Goal**: Add a bot player that can join a game room and play autonomously following valid game rules, enabling solo play and manual testing without needing other human players.
**Depends on**: Phase 24 (all prior phases complete)
**Plans**: 5 plans

Plans:

- [x] 25-01: Shared types (isBot) + Room bot infrastructure (addBot/removeBot)
- [x] 25-02: BotPlayer move selection logic (TDD)
- [x] 25-03: Wire bot into WebSocket handlers (add-bot/remove-bot, turn detection, auto-play)
- [x] 25-04: Client lobby UI bot controls (Add Bot, Remove, bot indicator)
- [x] 25-05: Integration tests + manual playtest verification

**Details:**
- BotPlayer.selectMove uses shared game rules (canPlayOnPile, getRankValue, RANK_ORDER)
- Strategy: play lowest valid rank group, pickup when no valid cards, random face-down
- 1-2s think delay with race condition guards
- Bot auto-ready in swap phase (500-1500ms staggered delay)
- Bot turn chaining for consecutive bot turns
- Host-only add/remove controls in both Lobby.vue and DiscordLobby.vue
- Robot emoji indicator for bot players
- 9 integration tests + 21 unit tests + 14 Room.bot tests

**Verified:** 6/6 must-haves (2026-02-22)
