### Phase 17: Platform Abstraction
- `ConnectionAdapterKey` and `RoomAdapterKey` provided via Vue inject but never consumed by any component
- `DiscordRoomAdapter.joinOrCreate()` method implemented but never called — DiscordLobby.vue calls useGameSocket directly

### Phase 19: Discord Room Management
- `DiscordLobby.vue` uses `window.location.reload()` in template (fragile global access, not Vue-idiomatic)
- Stale "Future Phase 19 enhancement" comment in DiscordRoomAdapter.ts
- Mobile Discord testing deferred due to ngrok/cloudflared limitations

### Phase 21: Card Playability Highlights
- `forcedIndices` prop passed by PlayingPhase.vue but not declared in PlayerCards.vue defineProps — silently dropped by Vue

### Phase 22: Mobile Card Categories
- Playability highlights (Phase 21 green glow / gray dim) absent in mobile carousel view — documented design decision, not a regression

### Phase 23: Frontend Testing
- No tests for `useCardCategories` composable
- No tests for client-side `cardRules.ts`
- No component tests for `PlayerCards.vue`, `PlayingPhase.vue`, `DiscordLobby.vue`
- `dangerouslyIgnoreUnhandledErrors: true` in vitest.config.ts (suppresses Bun/Docker WebSocket noise)

**Total:** 12 items across 5 phases
