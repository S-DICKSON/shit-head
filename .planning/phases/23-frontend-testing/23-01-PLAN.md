This factory is NOT a vi.mock — it's a helper that vi.mock factories call. Individual test files will use it like:
```typescript
vi.mock('@/composables/useGameSocket', () => {
  const { createMockSocket } = await import('@/test/mocks/useGameSocket.mock');
  let _cache: ReturnType<typeof createMockSocket> | null = null;
  return {
    useGameSocket: () => { if (!_cache) _cache = createMockSocket(); return _cache; },
    resolveWebSocketUrl: (await import('@/test/mocks/useGameSocket.mock')).resolveWebSocketUrl,
  };
});
```

NOTE: vi.mock factories do NOT support top-level await in the factory function. Instead, test files should import the factory via vi.hoisted or inline the mock directly. The recommended pattern for this project is to inline the mock per-file using the factory shape from createMockSocket as a reference, OR use `vi.mock` with synchronous factory that constructs refs inline. See the Research file Pattern 1 for the proven inline approach. The mock helper file is still valuable as the canonical reference for the mock shape and for the resetMockSocket utility.
