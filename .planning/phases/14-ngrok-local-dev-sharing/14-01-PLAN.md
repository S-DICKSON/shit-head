<task type="auto">
  <name>Task 1: Add WebSocket proxy and remove VITE_WS_URL</name>
  <files>
    packages/client/vite.config.ts
    docker-compose.yml
  </files>
  <action>
    **1. Update vite.config.ts** to add a WebSocket proxy for `/game-ws`:

    In the `proxy` section (currently only has `/api`), add a `/game-ws` entry:
    ```typescript
    proxy: {
      '/api': serverUrl,
      '/game-ws': {
        target: serverUrl.replace('http', 'ws'),
        ws: true,
      },
    }
    ```

    The `serverUrl` is already defined as `process.env.VITE_SERVER_URL || 'http://localhost:3000'`. The replace converts `http://` to `ws://` for WebSocket proxying. Vite's proxy (powered by http-proxy) supports WebSocket upgrade natively with `ws: true`.

    **2. Remove VITE_WS_URL from docker-compose.yml:**

    In the `client` service `environment` section, delete the line:
    ```
    - VITE_WS_URL=ws://localhost:3000/game-ws
    ```

    This is critical: when `VITE_WS_URL` is absent, the client's `useGameSocket.ts` falls back to deriving the WebSocket URL from `window.location.host` + `/game-ws`. In Docker dev mode, `window.location.host` is `localhost:5173`, and Vite's proxy will forward `/game-ws` to the server. Through ngrok, `window.location.host` will be the ngrok URL, and the same proxy path works.

    **Do NOT modify useGameSocket.ts** — its existing fallback logic is exactly what we need:
    ```typescript
    const serverUrl = import.meta.env.VITE_WS_URL;
    let wsUrl = serverUrl
      ? serverUrl
      : `${window.location.protocol === 'https:' ? 'wss:' : 'ws:'}//${window.location.host}/game-ws`;
    ```
    Without VITE_WS_URL, it falls back to the `window.location`-based URL, which works for both localhost and ngrok.
  </action>
  <verify>
    1. Run `make dev` and verify:
       - Client starts on port 5173
       - Server starts on port 3000
       - Open browser to http://localhost:5173 — app loads
       - Check browser DevTools Network tab: WebSocket connects to ws://localhost:5173/game-ws (proxied through Vite)
    2. Verify docker-compose.yml no longer has VITE_WS_URL
    3. Run `make lint` — all packages pass
  </verify>
  <done>
    Vite proxies /game-ws to the backend server. Client connects via window.location-derived URL through the Vite proxy. Docker Compose no longer sets VITE_WS_URL.
  </done>
</task>

<task type="auto">
  <name>Task 2: Add Makefile tunnel target</name>
  <files>
    Makefile
  </files>
  <action>
    Add a `tunnel` target to the Makefile that starts ngrok on port 5173.

    **Add to the .PHONY line:** append `tunnel` to the existing list.

    **Add the target:**
    ```makefile
    tunnel: ## Start ngrok tunnel for mobile testing (run make dev first)
    	@echo "Starting ngrok tunnel on port 5173..."
    	@echo "Share the https URL with mobile devices to test"
    	@echo ""
    	ngrok http 5173
    ```

    The `@echo` lines provide clear instructions. The user must have ngrok installed locally (`brew install ngrok` on macOS or download from ngrok.com). The target assumes `make dev` is already running in another terminal.

    **Important notes:**
    - ngrok runs on the HOST machine (not in Docker), which is correct because the Docker client port 5173 is mapped to the host.
    - The ngrok tunnel URL will be `https://xxxx.ngrok-free.app` — HTTPS by default.
    - The client will derive `wss://xxxx.ngrok-free.app/game-ws` from `window.location`, and Vite's proxy handles the forwarding.
    - HMR will NOT work over ngrok (it uses a separate WebSocket path `/__hmr`), but that's expected — HMR is for local dev only. The game itself works fine.
  </action>

    4. Open the ngrok URL in a mobile browser — game loads and WebSocket connects
