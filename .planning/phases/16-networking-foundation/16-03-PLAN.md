**docker-compose.discord.yml** - Create a new Docker Compose file for Discord Activity development. This runs the normal dev environment (client + server) PLUS a cloudflared tunnel pointing to the Vite dev server (port 5173, not the server directly — so Vite handles all proxy routing including /.proxy paths).

```yaml
# Discord Activity local development
# Extends the standard dev services with a cloudflared tunnel
# Usage: make dev-discord

services:
  client:
    build:
      context: .
      dockerfile: packages/client/Dockerfile
      target: dev
    ports:
      - "5173:5173"
    working_dir: /app/packages/client
    volumes:
      - ./packages/client:/app/packages/client
      - ./packages/shared:/app/packages/shared
      - /app/node_modules
      - /app/packages/client/node_modules
      - /app/packages/shared/node_modules
    environment:
      - NODE_ENV=development
    depends_on:
      - server

  server:
    build:
      context: .
      dockerfile: packages/server/Dockerfile
      target: dev
    ports:
      - "3000:3000"
    volumes:
      - ./packages/server:/app/packages/server
      - ./packages/shared:/app/packages/shared
      - /app/node_modules
      - /app/packages/server/node_modules
      - /app/packages/shared/node_modules
    environment:
      - NODE_ENV=development
      - PORT=3000

  tunnel:
    image: cloudflare/cloudflared:latest
    command: tunnel --no-autoupdate --url http://client:5173
    depends_on:
      - client
```

Key differences from docker-compose.tunnel.yml (which builds a production bundle + tunnels to server:3000):
- This runs the DEV environment (hot reload, Vite proxy rules active)
- Tunnel points to Vite client (port 5173), not directly to server
- Vite's proxy rules handle routing /.proxy/* to the backend
- This gives us the full Discord proxy path testing with HMR

Create DISCORD-SETUP.md at the project root with:

1. **Overview** section explaining Discord Activity proxy architecture (Activities run in iframe, all traffic through discordsays.com, /.proxy prefix stripped by Discord)

2. **URL Mapping Rules** section documenting:

| Client Path | Discord Proxy Path | Backend Path | Purpose |
|-------------|-------------------|--------------|---------|
| /api/* | /.proxy/api/* | /api/* | REST API calls |
| /game-ws | /.proxy/ws | /game-ws | WebSocket connection |

Explain: Discord's proxy adds `/.proxy` prefix. Vite dev server (in local dev) and production reverse proxy strip this prefix before forwarding to the backend.

3. **Local Development Setup** section:
   - Prerequisites: Docker, cloudflared (installed via Docker image, no local install needed)
   - Step 1: Create a Discord Application at discord.com/developers
   - Step 2: Enable Activities in the app settings
   - Step 3: Add URL Mapping in Discord Developer Portal:
     - Target: the cloudflared tunnel URL (shown in terminal when `make dev-discord` runs)
     - Root mapping: `/` -> tunnel URL
     - Prefix: `/.proxy/` -> tunnel URL
   - Step 4: Run `make dev-discord`
   - Step 5: Copy the cloudflared URL from terminal output
   - Step 6: Paste URL into Discord Developer Portal URL Mappings
   - Step 7: Launch Activity from Discord (voice channel -> Activities -> your app)

4. **Manual Testing Checklist** section (per user decision: manual checklist required):
   - [ ] cloudflared tunnel starts and shows URL
   - [ ] Discord Activity launches in iframe
   - [ ] WebSocket connects through /.proxy/ws path
   - [ ] Player can enter nickname and create room
   - [ ] Second player can join room via code
   - [ ] Both players see lobby state
   - [ ] Host can start game
   - [ ] Game starts successfully (cards dealt)
   - [ ] Connection drop shows reconnecting overlay
   - [ ] Reconnection succeeds and player rejoins room

5. **Production Deployment Checklist** section:
   - Configure URL mappings in Discord Developer Portal to point to production URL
   - Set ALLOWED_ORIGINS to include production domain
   - Ensure reverse proxy (Caddy) forwards /.proxy/* paths with prefix stripped
   - Test WebSocket upgrade through production proxy
   - Verify HTTPS (required for Discord Activities)

6. **Troubleshooting** section:
   - "WebSocket upgrade rejected": Check ALLOWED_ORIGINS includes discordsays.com (should be automatic via hostname check)
   - "Connection refused through proxy": Verify tunnel URL matches Discord URL Mapping
   - "HMR not working through tunnel": HMR uses /__hmr path which may not route through Discord proxy — this is expected, refresh manually
