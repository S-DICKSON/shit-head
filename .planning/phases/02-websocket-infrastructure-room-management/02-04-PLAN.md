  <action>
    Create `packages/server/src/websocket/handlers.ts`:

    1. **Imports:** Import RoomManager, clientMessageSchema from shared, ServerMessage types, nanoid
    2. **Singleton RoomManager:** Create and export a single RoomManager instance (module-level)
    3. **WebSocketData type:** Define `{ playerId: string, roomCode: string | null }` — attached to each ws connection via Bun's `ws.data`

    4. **handleMessage(ws, message, roomManager):**
       - Parse message string to JSON (catch parse errors -> send error response)
       - Validate with `clientMessageSchema.safeParse()` (not .parse — don't throw)
       - If validation fails: send `{ type: 'error', message: 'Invalid message', code: 'INVALID_MESSAGE' }`
       - Route by message.type:

         **'create-room':**
         - Call `roomManager.createRoom(ws.data.playerId, message.nickname)`
         - Subscribe ws to room topic: `ws.subscribe(roomCode)`
         - Send back to creator: `{ type: 'room-created', room: roomState, playerId: ws.data.playerId }`

         **'join-room':**
         - Call `roomManager.joinRoom(message.code, ws.data.playerId, message.nickname)`
         - If error (not found, full, started): send error message with appropriate code
         - If success: subscribe ws to room topic `ws.subscribe(message.code)`
         - Send to joiner: `{ type: 'room-joined', room: roomState, playerId: ws.data.playerId }`
         - Publish to room topic (all other players): `{ type: 'room-updated', room: roomState }`
         - Note: ws.publish sends to all OTHER subscribers (not the sender), which is correct here

         **'leave-room':**
         - Call `roomManager.leaveRoom(ws.data.playerId)`
         - Unsubscribe ws from room topic: `ws.unsubscribe(roomCode)`
         - Publish to room topic: `{ type: 'player-left', playerId: ws.data.playerId, room: updatedState }` (or `{ type: 'room-updated', room: updatedState }` if room still exists)
         - If room destroyed (host left): publish a special message or just let remaining connections handle it

         **'start-game':**
         - Call `roomManager.startGame(ws.data.playerId)`
         - If error (not host, not enough players): send error to caller
         - If success: publish to room topic `{ type: 'game-starting', countdown: 3 }` (3-second countdown per CONTEXT.md)
         - After countdown (use setTimeout 3000ms): publish `{ type: 'game-started' }` and update room status
         - Also send game-starting to the host (ws.send) since publish doesn't include sender

    5. **handleClose(ws, roomManager):**
       - Call `roomManager.leaveRoom(ws.data.playerId)` (same as leave-room)
       - Unsubscribe from topic
       - Publish room-updated to remaining players if room still exists

    6. **Helper function sendMessage(ws, msg: ServerMessage):** JSON.stringify and ws.send
    7. **Helper function publishToRoom(ws, topic: string, msg: ServerMessage):** JSON.stringify and ws.publish

    Write tests in `packages/server/src/__tests__/websocket.test.ts`:
    - Test that handleMessage with valid create-room message calls roomManager.createRoom
    - Test that handleMessage with invalid JSON sends error
    - Test that handleMessage with invalid message type sends INVALID_MESSAGE error
    - Test that handleClose calls roomManager.leaveRoom
    - Use mock/spy pattern for RoomManager methods and ws object
