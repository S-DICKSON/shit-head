  <behavior>
    **Room class** manages individual room state:
    - Constructor takes hostId and hostNickname, generates 6-char room code using nanoid with custom alphabet (uppercase letters + digits, excluding confusable chars: 0/O, 1/I/L, 5/S — alphabet: "2346789ABCDEFGHJKMNPQRTUVWXYZ")
    - `addPlayer(id, nickname)` -> adds player to room, returns success/error
    - `removePlayer(id)` -> removes player, returns whether room should be destroyed (host left)
    - `getState()` -> returns RoomState (from shared types) for broadcasting to clients
    - `canStart()` -> returns boolean (2+ players, status is 'waiting')
    - `startCountdown()` -> sets status to 'countdown'
    - `startGame()` -> sets status to 'playing'
    - Max 4 players enforced

    **RoomManager class** manages all rooms:
    - `createRoom(hostId, nickname)` -> creates Room, stores it, returns room code
    - `joinRoom(code, playerId, nickname)` -> finds room, adds player, returns RoomState or error
    - `leaveRoom(playerId)` -> finds player's room, removes them, may destroy room
    - `startGame(playerId)` -> validates player is host, room has enough players, starts countdown
    - `getRoom(code)` -> returns Room or undefined
    - `getRoomByPlayerId(playerId)` -> returns Room or undefined
    - Internal map: rooms by code, player-to-room index

    **Test cases (RED phase):**
    1. createRoom returns room with 6-char code from valid alphabet
    2. createRoom sets creator as host
    3. joinRoom adds player to existing room
    4. joinRoom returns error for non-existent room code
    5. joinRoom returns error when room is full (4 players)
    6. joinRoom returns error when game already started
    7. removePlayer removes player from room
    8. removePlayer destroys room when host leaves
    9. removePlayer transfers host when host leaves (CONTEXT says host leaving = disappear, so destroy room — per "No room idle timeout — room stays open until host leaves or game starts")
    10. startGame fails if caller is not host
    11. startGame fails if fewer than 2 players
    12. startGame succeeds with 2+ players and host calling
    13. getState returns correct RoomState shape
    14. Room codes are unique (create multiple rooms, all codes differ)
    15. Nickname validation: reject empty, reject > 20 chars
  </behavior>
  <implementation>
    **Room.ts:**
    - Import nanoid with custom alphabet for code generation
    - Store players as Map<string, { id: string, nickname: string, isHost: boolean }>
    - Status field: RoomStatus from shared types
    - All methods are synchronous (no async needed for in-memory state)

    **RoomManager.ts:**
    - Store rooms as Map<string, Room> (code -> Room)
    - Store player index as Map<string, string> (playerId -> roomCode)
    - All public methods return result objects: { success: true, data: ... } | { success: false, error: string, code: ErrorCode }
    - Clean separation: RoomManager handles lookup/routing, Room handles state logic

    **Important:** Do NOT use nanoid at the module level. Import it in the Room constructor or pass a code generator function. This keeps tests deterministic if needed (can mock the generator).
  </implementation>
</feature>
