  <files>

    packages/shared/src/types/room.ts

  <action>
    1. Install zod in shared package: `cd packages/shared && bun add zod`
    2. Install zod and nanoid in server package: `cd packages/server && bun add zod nanoid`

    3. Create `packages/shared/src/types/room.ts` with:
       - `Player` type: { id: string, nickname: string, isHost: boolean }
       - `LobbyPlayer` type: { id: string, nickname: string, isHost: boolean } (what clients see in lobby)
       - `RoomStatus` type: 'waiting' | 'countdown' | 'playing'
       - `RoomState` type: { code: string, players: LobbyPlayer[], status: RoomStatus, hostId: string, maxPlayers: 4, minPlayers: 2 }

    4. Create `packages/shared/src/types/messages.ts` with discriminated unions using `type` field:

       **Client-to-server messages:**
       - `{ type: 'create-room', nickname: string }` — Host creates a new room
       - `{ type: 'join-room', code: string, nickname: string }` — Player joins existing room
       - `{ type: 'leave-room' }` — Player leaves current room
       - `{ type: 'start-game' }` — Host starts the game

       **Server-to-client messages:**
       - `{ type: 'room-created', room: RoomState, playerId: string }` — Room created successfully
       - `{ type: 'room-joined', room: RoomState, playerId: string }` — Successfully joined room
       - `{ type: 'room-updated', room: RoomState }` — Room state changed (player join/leave)
       - `{ type: 'player-left', playerId: string, room: RoomState }` — A player left
       - `{ type: 'game-starting', countdown: number }` — Game countdown started
       - `{ type: 'game-started' }` — Game has begun (placeholder for Phase 3)
       - `{ type: 'error', message: string, code: string }` — Error response

       Export union types: `ClientMessage` (union of all client messages), `ServerMessage` (union of all server messages).

       Error codes to define as const enum or string literal union: 'ROOM_NOT_FOUND', 'ROOM_FULL', 'GAME_ALREADY_STARTED', 'NOT_HOST', 'NOT_ENOUGH_PLAYERS', 'INVALID_NICKNAME', 'INVALID_MESSAGE'.
  </action>
  <verify>
    Run `cd packages/shared && bun run tsc --noEmit` (or equivalent type check). Verify no TypeScript errors. Verify zod appears in shared/package.json dependencies. Verify nanoid and zod appear in server/package.json dependencies.
  </verify>
  <done>
    Room and player types are defined. All client-to-server and server-to-client message types are defined as discriminated unions. Dependencies installed.
  </done>

<task type="auto">
  <name>Task 2: Create Zod schemas and update shared exports</name>
  <files>
    packages/shared/src/schemas/messages.ts
    packages/shared/src/index.ts
  </files>
  <action>
    1. Create `packages/shared/src/schemas/messages.ts` with Zod schemas mirroring every message type:

       **Client message schemas:**
       - `createRoomSchema`: z.object({ type: z.literal('create-room'), nickname: z.string().min(1).max(20).trim() })
       - `joinRoomSchema`: z.object({ type: z.literal('join-room'), code: z.string().length(6), nickname: z.string().min(1).max(20).trim() })
       - `leaveRoomSchema`: z.object({ type: z.literal('leave-room') })
       - `startGameSchema`: z.object({ type: z.literal('start-game') })
       - `clientMessageSchema`: z.discriminatedUnion('type', [createRoomSchema, joinRoomSchema, leaveRoomSchema, startGameSchema])

       **Server message schemas (for completeness/testing):**
       - Define schemas for each server message type
       - `serverMessageSchema`: z.discriminatedUnion('type', [...all server schemas])

       Export all individual schemas and the union schemas.

       **IMPORTANT:** Use `z.infer<typeof schema>` to derive the TypeScript types in messages.ts rather than manually defining them. This ensures types and schemas always match. Approach: Define schemas in schemas/messages.ts, then in types/messages.ts, import schemas and use z.infer to derive types. Or alternatively, define types in messages.ts and keep schemas as runtime validators. Choose whichever approach avoids circular dependencies -- the cleanest pattern is: schemas define the shape, types are inferred from schemas.

    2. Update `packages/shared/src/index.ts` to re-export everything:
       - `export * from './types/messages'`
       - `export * from './types/room'`
       - `export * from './schemas/messages'`
       - Keep existing `APP_VERSION` export

    3. Verify the circular dependency situation: if types import from schemas and schemas import from types, refactor so schemas are the source of truth and types are inferred. The pattern should be:
       - schemas/messages.ts: defines Zod schemas (imports room types for nested objects)
       - types/messages.ts: imports schemas, exports `type ClientMessage = z.infer<typeof clientMessageSchema>` etc.
       - types/room.ts: standalone room/player types (no imports from schemas)
  </action>
  <verify>

  </verify>
