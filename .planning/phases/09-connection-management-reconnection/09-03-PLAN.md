<objective>
Add client-side reconnection support with localStorage identity persistence and update server WebSocket upgrade to reuse stored playerIds.

Purpose: When a player refreshes their browser or loses connection momentarily, they need to rejoin their game seamlessly. The client stores its playerId and roomCode in localStorage, includes the playerId as a query param when reconnecting, and automatically sends a `reconnect` message to the server. The server-side upgrade endpoint reuses the provided playerId instead of generating a new one.

Output: Updated useGameSocket.ts with localStorage persistence and auto-reconnect logic, updated index.ts with playerId query param support.
</objective>

    ```typescript
    if (storedPlayerId) {
      const separator = wsUrl.includes('?') ? '&' : '?';
      wsUrl += `${separator}playerId=${encodeURIComponent(storedPlayerId)}`;
    }
    ```

    ```typescript
      if (newId) {
        localStorage.setItem('shithead-player-id', newId);
      }
    }));

    // Persist roomCode to localStorage when room state changes
    scope.run(() => watch(roomState, (newRoom) => {
      if (newRoom) {
        localStorage.setItem('shithead-room-code', newRoom.code);
      }
    ```

    ```typescript
      if (newStatus === 'OPEN' && storedPlayerId && storedRoomCode) {
        // Send reconnect message to rejoin room
        wsSend(JSON.stringify({ type: 'reconnect', roomCode: storedRoomCode }));
      }
    }));
    ```
