  `shuffleDeck(cards: Card[]): Card[]`
  - Takes an array of cards, returns a new shuffled array (Fisher-Yates)
  - Does NOT mutate the input array
  - Returns same number of cards

  Test cases:
  - shuffleDeck(createDeck()) returns 54 cards
  - shuffleDeck does not mutate original array
  - shuffleDeck produces different order from input (statistical: run twice, at least one differs)
  - shuffleDeck contains all original cards (same set, different order)

  **GameEngine (packages/server/src/game/GameEngine.ts):**

  `GameEngine` class with:

  `static createGame(players: { id: string; nickname: string }[], dealerIndex: number): GameState`
  - Creates deck, shuffles, deals to all players
  - Each player gets 3 face-down, 3 face-up, 3 hand cards
  - Dealing order: all face-down first (3 per player in order), then all face-up (3 per player), then all hand cards (3 per player) -- simulates real dealing
  - Remaining cards become drawPile
  - discardPile starts empty
  - currentPlayerIndex set to (dealerIndex + 1) % players.length (player after dealer goes first)
  - phase set to 'swapping' (dealing transitions directly to swap phase)

  `static getPlayerView(state: GameState, playerId: string): PlayerGameView`
  - Returns the player-specific view of the game state
  - Player sees: their own hand, their own faceUp, count of their own faceDown
  - Player sees opponents as OpponentView: nickname, faceUp cards, counts for faceDown and hand
  - drawPileCount = state.drawPile.length
  - discardPile = state.discardPile (all visible)
  - Throws if playerId not found in game state

  `static nextDealerIndex(currentDealerIndex: number, playerCount: number): number`
  - Returns (currentDealerIndex + 1) % playerCount
  - For DECK-04: dealer rotates clockwise

  Test cases for GameEngine:
  - createGame with 2 players: each gets 3+3+3=9 cards, drawPile = 54 - 18 = 36 cards
  - createGame with 3 players: each gets 9 cards, drawPile = 54 - 27 = 27 cards
  - createGame with 4 players: each gets 9 cards, drawPile = 54 - 36 = 18 cards
  - createGame sets phase to 'swapping'
  - createGame sets discardPile to empty array
  - createGame sets currentPlayerIndex to (dealerIndex + 1) % playerCount
  - Each player's faceDown has exactly 3 cards
  - Each player's faceUp has exactly 3 cards
  - Each player's hand has exactly 3 cards
  - All 54 cards accounted for (player cards + drawPile = 54)
  - No duplicate cards across all players and drawPile
  - getPlayerView returns correct hand for requesting player
  - getPlayerView returns correct faceUp for requesting player
  - getPlayerView returns faceDownCount (not actual cards) for requesting player
  - getPlayerView opponents have faceUp cards visible
  - getPlayerView opponents have handCount (not actual cards)
  - getPlayerView opponents have faceDownCount (not actual cards)
  - getPlayerView throws for unknown playerId
  - nextDealerIndex wraps around: (3, 4) -> 0
  - nextDealerIndex increments: (0, 4) -> 1
  </behavior>
  <implementation>
  **Deck.ts:**
  - Fisher-Yates (Knuth) shuffle: iterate from end, swap with random index in [0, i]
  - Use `Math.random()` (no need for crypto-grade randomness for a card game)
  - Return new array via spread or slice before shuffling

  **GameEngine.ts:**
  - Import createDeck, Card, GameState, PlayerGameState, PlayerGameView, OpponentView from @shit-head/shared
  - Import shuffleDeck from ./Deck
  - createGame: build PlayerGameState[] by slicing shuffled deck:
    - Cards 0...(3*N-1) = face-down (3 per player, round-robin)
    - Cards (3*N)...(6*N-1) = face-up (3 per player, round-robin)
    - Cards (6*N)...(9*N-1) = hand (3 per player, round-robin)
    - Cards (9*N)...53 = drawPile
    - Alternative simpler approach: just deal sequentially: player[0].faceDown gets cards[0..2], player[1].faceDown gets cards[3..5], etc.
    - Use the simpler sequential slice approach. Round-robin dealing is visual -- in code, the shuffle already randomizes.
  - getPlayerView: find player in state.players, map others to OpponentView
  - nextDealerIndex: simple modular arithmetic
  </implementation>
