  <name>Task 2: Wire dealing into WebSocket start-game handler</name>

Update the `start-game` case in `handleMessage` in `packages/server/src/websocket/handlers.ts`:

The current flow is:
1. Validate host -> startCountdown() -> send game-starting -> setTimeout 3s -> startGame() -> send game-started

The new flow keeps the countdown but after startGame(), deals cards and sends player-specific views:

In the setTimeout callback (after the existing `room.startGame()` call), replace the simple `game-started` broadcast with per-player `game-dealt` messages:

```typescript
// After 3-second countdown, start the game and deal
setTimeout(() => {
  const room = manager.getRoom(roomCode);
  if (room) {
    room.startGame(); // This now also deals cards

    // Send player-specific game-dealt messages
    const playerIds = room.getPlayerIds();
    for (const pid of playerIds) {
      const view = room.getPlayerView(pid);
      if (view) {
        const dealMsg = {
          type: 'game-dealt' as const,
          phase: view.phase,
          hand: view.hand,
          faceUp: view.faceUp,
          faceDownCount: view.faceDownCount,
          opponents: view.opponents,
          drawPileCount: view.drawPileCount,
          discardPile: view.discardPile,
          currentPlayerIndex: view.currentPlayerIndex,
          dealerIndex: view.dealerIndex,
        };

        // For the host (who initiated), send directly
        if (pid === ws.data.playerId) {
          sendMessage(ws, dealMsg);
        } else {
          // For other players, publish to room topic
          // NOTE: ws.publish sends to all subscribers EXCEPT the sender
          // Since we need to send to specific players, we publish the same
          // message to all -- each player gets the same structure but the
          // content is player-specific, so we need a different approach.
        }
      }
    }
  }
}, 3000);
```

**IMPORTANT ARCHITECTURE NOTE:** Bun's `ws.publish(topic, msg)` broadcasts the SAME message to all subscribers. But we need to send DIFFERENT messages to each player (each player gets their own card view). This means we CANNOT use publish for game-dealt messages.

**Solution:** We need access to each player's WebSocket connection. The current architecture only has the host's `ws` reference in the setTimeout closure. To solve this properly:

1. **Add a player WebSocket registry to handlers.ts:** Create a `Map<string, ServerWebSocket<WebSocketData>>` at module level to track connected WebSocket instances by playerId.

   ```typescript
   // Player WebSocket registry for targeted messaging
   const playerSockets = new Map<string, ServerWebSocket<WebSocketData>>();
   ```

2. **Register on connection open:** Export a `handleOpen` function:
   ```typescript
   export function handleOpen(ws: ServerWebSocket<WebSocketData>): void {
     playerSockets.set(ws.data.playerId, ws);
   }
   ```

3. **Unregister on connection close:** In the existing `handleClose` function, add:
   ```typescript
   playerSockets.delete(ws.data.playerId);
   ```

4. **Update server index.ts:** In the `websocket.open` handler, call `handleOpen(ws)`:
   ```typescript
   open(ws) {
     handleOpen(ws);
     console.log(`Player ${ws.data.playerId} connected`);
   },
   ```
   Import `handleOpen` from `./websocket/handlers`.

5. **Use registry in start-game handler:** In the setTimeout callback:
   ```typescript
   const playerIds = room.getPlayerIds();
   for (const pid of playerIds) {
     const view = room.getPlayerView(pid);
     const playerWs = playerSockets.get(pid);
     if (view && playerWs) {
       sendMessage(playerWs, {
         type: 'game-dealt',
         phase: view.phase,
         hand: view.hand,
         faceUp: view.faceUp,
         faceDownCount: view.faceDownCount,
         opponents: view.opponents,
         drawPileCount: view.drawPileCount,
         discardPile: view.discardPile,
         currentPlayerIndex: view.currentPlayerIndex,
         dealerIndex: view.dealerIndex,
       });
     }
   }
   ```

6. **Remove the old game-started messages** (the two `sendMessage(ws, { type: 'game-started' })` and `publishToRoom(ws, roomCode, { type: 'game-started' })` lines). The `game-dealt` message replaces `game-started` -- receiving dealt cards IS the signal that the game has started.

Also update `packages/server/src/index.ts` to import and call `handleOpen`:
- Add `handleOpen` to the import from `./websocket/handlers`
- Call `handleOpen(ws)` in the `websocket.open` callback
