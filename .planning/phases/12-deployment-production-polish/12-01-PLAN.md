  <files>infra/opentofu/main.tf, infra/opentofu/variables.tf, infra/opentofu/outputs.tf</files>
  <action>
    **Replace** the entire contents of `main.tf`, `variables.tf`, and `outputs.tf`. These currently have Cloudflare provider configuration that is being replaced with Oracle Cloud.

    **main.tf** must contain:
    1. `terraform` block requiring version >= 1.8 and `oracle/oci` provider ~> 6.0
    2. `provider "oci"` using var references for tenancy_ocid, user_ocid, fingerprint, private_key_path, region
    3. `data "oci_identity_availability_domain"` to get AD name (ad_number = 1)
    4. `data "oci_core_images"` filtering for Canonical Ubuntu 24.04 on VM.Standard.A1.Flex shape, sorted by TIMECREATED DESC
    5. `resource "oci_core_vcn"` with CIDR 10.0.0.0/16, dns_label "shithead"
    6. `resource "oci_core_internet_gateway"` attached to VCN
    7. `resource "oci_core_route_table"` with default route (0.0.0.0/0) to internet gateway
    8. `resource "oci_core_security_list"` with ingress rules for:
       - TCP port 22 (SSH) from 0.0.0.0/0
       - TCP port 80 (HTTP) from 0.0.0.0/0
       - TCP port 443 (HTTPS) from 0.0.0.0/0
       - All egress allowed
    9. `resource "oci_core_subnet"` in VCN with CIDR 10.0.1.0/24, using the route table and security list
    10. `resource "oci_core_instance"` for the game server:
        - shape: VM.Standard.A1.Flex
        - shape_config: 4 OCPU, 24 GB RAM (Always Free max)
        - source: Ubuntu ARM64 image, 100 GB boot volume
        - VNIC: public subnet, assign_public_ip = true
        - metadata: ssh_authorized_keys from var.ssh_public_key, user_data from cloud-init.yaml (base64encoded)
        - display_name: "shithead-game-server"

    - `tenancy_ocid` (string, sensitive)

<task type="auto">
  <name>Task 2: Create cloud-init script for VPS initialization</name>
  <files>infra/opentofu/cloud-init.yaml</files>
  <action>
    Create `infra/opentofu/cloud-init.yaml` as a cloud-config YAML file that runs on first boot of the Oracle Cloud instance.

    The cloud-init script must:
    1. Set `package_update: true` and `package_upgrade: true`
    2. Install packages: apt-transport-https, ca-certificates, curl, gnupg, lsb-release
    3. In `runcmd`:
       a. Install Docker via `curl -fsSL https://get.docker.com | sh`
       b. Add `ubuntu` user to docker group: `usermod -aG docker ubuntu`
       c. Open iptables port 80: `iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT`
       d. Open iptables port 443: `iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT`
       e. Persist iptables rules: `netfilter-persistent save`
       f. Create app directory: `mkdir -p /opt/shithead`
       g. Set ownership: `chown ubuntu:ubuntu /opt/shithead`
       h. Enable and start Docker service
       i. Install Caddy:
          - Add Caddy GPG key and APT repository (per official Caddy install docs for Debian/Ubuntu)
          - `apt-get update && apt-get install -y caddy`
       j. Stop Caddy service initially (will be configured later during deploy): `systemctl stop caddy`
    4. Write the systemd service file for the game container via `write_files`:
       - Path: `/etc/systemd/system/shithead-game.service`
       - Content: systemd unit that runs the Docker container (see RESEARCH.md Pattern 3):
         - After=docker.service, Requires=docker.service
         - Type=simple, Restart=on-failure, RestartSec=15
         - ExecStartPre: stop and remove existing container, pull latest from ghcr.io
         - ExecStart: `docker run --name shithead-game --rm --log-driver=journald -p 127.0.0.1:3000:3000 --env-file /opt/shithead/.env ghcr.io/OWNER/shithead-server:latest`
           - NOTE: Bind to 127.0.0.1:3000 only (Caddy will reverse proxy, no direct access)
           - Use placeholder OWNER that will be replaced at deploy time
         - ExecStop: `docker stop -t 60 shithead-game`
         - TimeoutStartSec=120, TimeoutStopSec=65
         - WantedBy=multi-user.target
    5. Write the Caddyfile template via `write_files`:
       - Path: `/etc/caddy/Caddyfile`
       - Content: Placeholder that will be updated during first deploy
       - Initially just: `# Configured by deployment pipeline`
    6. Set `final_message: "Cloud-init complete. Docker and Caddy installed. Ports 80/443 open."`

    IMPORTANT: The cloud-init must handle Oracle Cloud's dual-firewall requirement (Security Lists + iptables). The Security List is handled by OpenTofu; iptables is handled here in cloud-init.
  </action>

  </verify>
  <done>

  </done>
