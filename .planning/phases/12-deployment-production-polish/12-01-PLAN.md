<task type="auto">
  <name>Task 1: Update server index.ts for production deployment</name>
  <files>packages/server/src/index.ts</files>
  <action>
  Rewrite packages/server/src/index.ts to be production-ready for split deployment:

  1. **Remove static file serving** — Delete the STATIC_DIR, serveStatic, MIME_TYPES, getMimeType logic. In split deployment, CF Pages serves the client. Return 404 for any non-health, non-WebSocket path.

  2. **Add Origin validation for WebSocket upgrade** — Read `ALLOWED_ORIGINS` from env var (comma-separated). In development, also allow `http://localhost:5173` and `http://localhost:4173`. In production (`NODE_ENV=production`), validate the `Origin` header against the allowlist. Reject with 403 if not in list. Log rejected origins with `console.warn`.

  3. **Add health check metrics** — Enhance the `/health` endpoint to return:
     - `status: 'ok'`
     - `version: APP_VERSION`
     - `uptime: process.uptime()`
     - `activeRooms: roomManager.getRoomCount()`
     - `activePlayers: roomManager.getPlayerCount()`
     - `activeConnections: activeConnections.size`
     Add CORS header `Access-Control-Allow-Origin: *` on health endpoint (public monitoring).

  4. **Add connection tracking** — Create a `Set<ServerWebSocket<WebSocketData>>` called `activeConnections`. Add to set in `websocket.open`, remove in `websocket.close`.

  5. **Add graceful shutdown** — Add `process.on('SIGTERM', ...)` handler that:
     - Logs "SIGTERM received, starting graceful shutdown"
     - Calls `server.stop()` to stop accepting new connections
     - Sends `ws.close(1000, 'Server shutting down')` to all active connections
     - Waits up to 55 seconds for connections to close (polling every 100ms)
     - Force exits with `process.exit(0)` on timeout
     - Exits cleanly when all connections close

  6. **Log startup info** — After server starts, log:
     - `Server listening on port ${server.port}`
     - `Environment: ${NODE_ENV}`
     - `Allowed origins: ${ALLOWED_ORIGINS.join(', ')}`

  Keep the existing reconnection playerId query param logic. Keep the existing handleOpen/handleMessage/handleClose/handleOpen integration. Remove the `join` and `path` imports (no longer needed without static file serving).

  Reference Pattern 2 from research for the exact structure.

  <name>Task 2: Add room activity tracking and cleanup to RoomManager</name>
  <files>packages/server/src/rooms/RoomManager.ts</files>
  <action>
  Update RoomManager to track room activity and clean up abandoned rooms:

  1. **Add activity tracking** — Add a `private lastActivityTimes: Map<string, number>` field. Initialize in constructor.

  2. **Add markActivity method** — Public method `markActivity(roomCode: string): void` that sets `this.lastActivityTimes.set(roomCode, Date.now())`.

  3. **Call markActivity** in existing methods:
     - `createRoom()` — after creating room
     - `joinRoom()` — after successful join
     - `leaveRoom()` — on player leave (room still active)
     - `startGame()` — on game start

  4. **Add cleanupAbandonedRooms** — Private method that:
     - Gets current timestamp
     - Iterates `lastActivityTimes` entries
     - For rooms inactive > 24 hours (24 * 60 * 60 * 1000 ms):
       - Logs `Cleaning up abandoned room: ${roomCode}`
       - Removes all players from playerRoomIndex
       - Deletes room from rooms map
       - Deletes from lastActivityTimes

  5. **Start cleanup interval** — In constructor, add `setInterval(() => this.cleanupAbandonedRooms(), 5 * 60 * 1000)` (every 5 minutes).

  6. **Add getter methods** (if not present):
     - `getRoomCount(): number` — returns `this.rooms.size`
     - `getPlayerCount(): number` — returns `this.playerRoomIndex.size`

  7. **Clean up lastActivityTimes in destroyRoom** — When a room is destroyed, also delete its lastActivityTimes entry.

  Note: The existing `destroyRoom` method already handles player index cleanup. Just add `this.lastActivityTimes.delete(code)` to it. Same for `leaveRoom` when `shouldDestroy` is true.
