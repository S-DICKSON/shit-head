  <action>
    **Replace** the entire contents of `.github/workflows/deploy.yml`. The old workflow deployed to Cloudflare Pages + Fly.io using SOPS. The new workflow deploys to Oracle Cloud VPS using Infisical.

    **Workflow structure:**

    ```yaml
    name: Deploy to Production
    on:
      workflow_dispatch:
      push:
        branches: [main]
    ```

    **Single job: `deploy`**
    - runs-on: ubuntu-latest
    - permissions: contents: read, packages: write, id-token: write (id-token for Infisical OIDC)

    **Steps:**

    1. **Checkout code** - actions/checkout@v4

    2. **Fetch Infisical secrets** - Use `Infisical/secrets-action@v1.0.6` with:
       - `method: oidc` (preferred) OR fall back to `method: service-token` with token from `${{ secrets.INFISICAL_SERVICE_TOKEN }}`
       - `env-slug: production`
       - `project-slug: shithead-game`
       - `export-type: env` (exports as environment variables)
       - This injects: VPS_SSH_PRIVATE_KEY, VPS_PUBLIC_IP, DOMAIN, ALLOWED_ORIGINS

       NOTE: Use `secrets.INFISICAL_SERVICE_TOKEN` approach since OIDC requires more Infisical setup. The action should look like:
       ```yaml
       - name: Fetch Infisical secrets
         uses: Infisical/secrets-action@v1.0.6
         with:
           client-id: ${{ secrets.INFISICAL_CLIENT_ID }}
           client-secret: ${{ secrets.INFISICAL_CLIENT_SECRET }}
           env-slug: production
           project-slug: shithead-game
           export-type: env
       ```
       This makes all Infisical secrets available as env vars in subsequent steps.

    3. **Set up Docker Buildx** - docker/setup-buildx-action@v3

    4. **Login to GHCR** - docker/login-action@v3 with:
       - registry: ghcr.io
       - username: ${{ github.actor }}
       - password: ${{ secrets.GITHUB_TOKEN }}

    5. **Build and push ARM64 image** - docker/build-push-action@v6 with:
       - context: . (project root, Dockerfile expects this)
       - file: packages/server/Dockerfile
       - push: true
       - tags: ghcr.io/${{ github.repository_owner }}/shithead-server:latest,ghcr.io/${{ github.repository_owner }}/shithead-server:${{ github.sha }}
       - platforms: linux/arm64
       - target: production
       - cache-from: type=gha
       - cache-to: type=gha,mode=max

    6. **Setup SSH** - webfactory/ssh-agent@v0.9.1 with:
       - ssh-private-key: ${{ env.VPS_SSH_PRIVATE_KEY }}

    7. **Deploy to Oracle Cloud VPS** - SSH to VPS with all GitHub Actions variables resolved BEFORE the heredoc.

       **CRITICAL HEREDOC PATTERN:** GitHub Actions expressions like `${{ secrets.* }}`, `${{ github.* }}`, and `${{ env.* }}` are ONLY interpolated by the GitHub Actions runner, NOT inside a remote SSH session. You MUST ensure all `${{ }}` expressions are resolved on the runner side before being sent to the remote host.

       Use step-level `env:` to expose needed values as shell variables, then use a **non-quoted heredoc** (no quotes around the delimiter) so the runner's shell interpolates the variables before sending them over SSH:

       ```yaml
       - name: Deploy to Oracle Cloud VPS
         env:
           GHCR_TOKEN: ${{ secrets.GITHUB_TOKEN }}
           GHCR_ACTOR: ${{ github.actor }}
           REPO_OWNER: ${{ github.repository_owner }}
           DEPLOY_DOMAIN: ${{ env.DOMAIN }}
           DEPLOY_ORIGINS: ${{ env.ALLOWED_ORIGINS }}
         run: |
           ssh -o StrictHostKeyChecking=no ubuntu@${{ env.VPS_PUBLIC_IP }} << ENDSSH
             # Login to GHCR (variables interpolated by runner before SSH)
             echo "${GHCR_TOKEN}" | docker login ghcr.io -u ${GHCR_ACTOR} --password-stdin

             # Pull latest image
             docker pull ghcr.io/${REPO_OWNER}/shithead-server:latest

             # Write .env file for the container
             cat > /opt/shithead/.env << ENVEOF
           NODE_ENV=production
           PORT=3000
           ALLOWED_ORIGINS=${DEPLOY_ORIGINS}
           ENVEOF

             # Update systemd service with correct image owner
             sudo sed -i "s|ghcr.io/OWNER/|ghcr.io/${REPO_OWNER}/|g" /etc/systemd/system/shithead-game.service
             sudo systemctl daemon-reload

             # Configure Caddy with domain
             cat | sudo tee /etc/caddy/Caddyfile << CADDYEOF
           ${DEPLOY_DOMAIN} {
               reverse_proxy localhost:3000
               log {
                   output file /var/log/caddy/shithead.log
               }
           }
           CADDYEOF
             sudo systemctl reload caddy || sudo systemctl restart caddy

             # Restart game service
             sudo systemctl enable shithead-game
             sudo systemctl restart shithead-game

             # Wait for startup
             sleep 10

             # Health check
             curl -f http://localhost:3000/health || exit 1

             echo "Deployment successful!"
           ENDSSH
       ```

       **Key points:**
       - The outer heredoc `<< ENDSSH` is **non-quoted** (no quotes around ENDSSH) so `${GHCR_TOKEN}`, `${REPO_OWNER}`, etc. are interpolated by the GitHub Actions runner's shell BEFORE being sent via SSH.
       - The inner heredocs (`ENVEOF`, `CADDYEOF`) are also non-quoted so `${DEPLOY_ORIGINS}` and `${DEPLOY_DOMAIN}` are interpolated.
       - All values come from step-level `env:` which resolves `${{ }}` expressions on the runner.
       - `${{ env.VPS_PUBLIC_IP }}` in the ssh command itself (outside the heredoc) is fine -- GitHub Actions resolves it directly.
       - Do NOT use `${{ }}` syntax anywhere inside the heredoc body. All values must flow through shell variables set in `env:`.

    8. **Post-deploy health check from outside** (optional but good):
       ```bash
       sleep 5
       curl -f https://${{ env.DOMAIN }}/health || echo "External health check failed (DNS/SSL may still be propagating)"
       ```

    **IMPORTANT:** Remove ALL references to SOPS, age, Cloudflare, Fly.io. This is a complete replacement.

    ```yaml
    name: Rollback to Previous Version
    on:
      workflow_dispatch:
        inputs:
          target_sha:
            description: 'Git SHA to rollback to (must have been deployed previously)'

            type: string
    ```

    **Single job: `rollback`**
    - runs-on: ubuntu-latest
    - permissions: contents: read, packages: read, id-token: write

    **Steps:**

    1. **Checkout code** (at target SHA for reference, not strictly needed but consistent)
       - actions/checkout@v4 with ref: ${{ inputs.target_sha }}

    2. **Fetch Infisical secrets** (same as deploy workflow)
       - Infisical/secrets-action@v1.0.6 with client-id/client-secret, production env

    3. **Setup SSH** - webfactory/ssh-agent@v0.9.1 with:
       - ssh-private-key: ${{ env.VPS_SSH_PRIVATE_KEY }}

    4. **Rollback on VPS** - SSH to pull specific SHA tag and restart.

       **CRITICAL HEREDOC PATTERN (same as deploy):** Use step-level `env:` to resolve all GitHub Actions expressions, then a non-quoted heredoc:

       ```yaml
       - name: Rollback on VPS
         env:
           REPO_OWNER: ${{ github.repository_owner }}
           TARGET_SHA: ${{ inputs.target_sha }}
         run: |
           ssh -o StrictHostKeyChecking=no ubuntu@${{ env.VPS_PUBLIC_IP }} << ENDSSH
             # Pull specific version
             docker pull ghcr.io/${REPO_OWNER}/shithead-server:${TARGET_SHA}

             # Tag it as latest locally for systemd service
             docker tag ghcr.io/${REPO_OWNER}/shithead-server:${TARGET_SHA} \
               ghcr.io/${REPO_OWNER}/shithead-server:latest

             # Restart service (picks up new :latest)
             sudo systemctl restart shithead-game

             # Wait and health check
             sleep 10
             curl -f http://localhost:3000/health || exit 1

             echo "Rollback to ${TARGET_SHA} successful!"
           ENDSSH
       ```

       **Key points:**
       - Non-quoted heredoc `<< ENDSSH` so `${REPO_OWNER}` and `${TARGET_SHA}` are interpolated by the runner.
       - `${{ env.VPS_PUBLIC_IP }}` in the ssh command (outside heredoc) is fine.
       - No `${{ }}` syntax inside the heredoc body.
