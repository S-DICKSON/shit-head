  <name>Task 1: Create multi-stage Dockerfiles for client and server</name>
  <files>
    packages/client/Dockerfile

  </files>
  <action>
Create Dockerfiles following research patterns. Use oven/bun:1 as base image for both.

1. **packages/server/Dockerfile** (multi-stage):

   Stage "base": FROM oven/bun:1, WORKDIR /app

   Stage "dev" (from base):
   - COPY root package.json and bun.lockb
   - COPY packages/server/package.json and packages/shared/package.json into correct paths
   - RUN bun install
   - COPY all source (will be overridden by volume mounts in dev)
   - EXPOSE 3000
   - CMD ["bun", "--watch", "packages/server/src/index.ts"]

   Stage "production" (from base):
   - COPY root package.json and bun.lockb
   - COPY packages/server/package.json and packages/shared/package.json
   - RUN bun install --frozen-lockfile --production
   - COPY packages/server/ ./packages/server/
   - COPY packages/shared/ ./packages/shared/
   - EXPOSE 3000
   - ENV NODE_ENV=production
   - CMD ["bun", "packages/server/src/index.ts"]

2. **packages/client/Dockerfile** (multi-stage):

   Stage "base": FROM oven/bun:1, WORKDIR /app

   Stage "dev" (from base):
   - COPY root package.json and bun.lockb
   - COPY packages/client/package.json and packages/shared/package.json into correct paths
   - RUN bun install
   - COPY all source
   - EXPOSE 5173
   - CMD ["bunx", "vite", "--host"]

   Stage "build" (from base):
   - COPY root package.json and bun.lockb
   - COPY packages/client/package.json and packages/shared/package.json
   - RUN bun install --frozen-lockfile
   - COPY packages/client/ ./packages/client/
   - COPY packages/shared/ ./packages/shared/
   - RUN cd packages/client && bunx vite build

   Stage "production" (using nginx or a simple static server):
   - FROM nginx:alpine AS production (for serving static files)
   - COPY --from=build /app/packages/client/dist /usr/share/nginx/html
   - EXPOSE 80
   - OR simpler: use Bun to serve static files:
     FROM oven/bun:1 AS production
     WORKDIR /app
     COPY --from=build /app/packages/client/dist ./dist
     Create a minimal static file server with Bun.serve() that serves from ./dist
   - For simplicity and consistency (Bun everywhere), use a tiny Bun static server.
   - Actually, for production on Render the client will be deployed as a static site (no server needed). So the production stage just needs the built dist/ directory. Use nginx:alpine for production — it's the standard for static sites and Render can serve it.

3. **.dockerignore**:
   - node_modules, .git, dist, *.md (except README), .env*, .terraform, .tofu, *.tfstate*, .idea, .planning

Important Docker notes:
- The build context for both Dockerfiles is the PROJECT ROOT (not the package directory) because they need access to root package.json, bun.lockb, and the shared package.
- Volume mounts in docker-compose.yml will override the COPY'd source in dev mode, enabling hot reload.
- The node_modules volume mount trick (`/app/node_modules` as anonymous volume) preserves container node_modules when source is mounted.

<task type="auto">
  <name>Task 2: Create Docker Compose files and Makefile</name>
  <files>
    docker-compose.yml
    docker-compose.prod.yml
    Makefile
  </files>
  <action>
1. **docker-compose.yml** (development):
   ```yaml
   services:
     client:
       build:
         context: .
         dockerfile: packages/client/Dockerfile
         target: dev
       ports:
         - "5173:5173"
       volumes:
         - ./packages/client:/app/packages/client
         - ./packages/shared:/app/packages/shared
         - /app/node_modules
         - /app/packages/client/node_modules
       environment:
         - NODE_ENV=development
       depends_on:
         - server

     server:
       build:
         context: .
         dockerfile: packages/server/Dockerfile
         target: dev
       ports:
         - "3000:3000"
       volumes:
         - ./packages/server:/app/packages/server
         - ./packages/shared:/app/packages/shared
         - /app/node_modules
         - /app/packages/server/node_modules
       environment:
         - NODE_ENV=development
         - PORT=3000
   ```

   Important: Anonymous volumes for node_modules prevent host node_modules from overriding container's installed dependencies.

2. **docker-compose.prod.yml** (production-like):
   ```yaml
   services:
     client:
       build:
         context: .
         dockerfile: packages/client/Dockerfile
         target: production
       ports:
         - "8080:80"
       environment:
         - NODE_ENV=production

     server:
       build:
         context: .
         dockerfile: packages/server/Dockerfile
         target: production
       ports:
         - "3000:3000"
       environment:
         - NODE_ENV=production
         - PORT=3000
   ```

   No volumes — uses built artifacts only.

3. **Makefile**:
   ```makefile
   .PHONY: help dev start build test clean lint type-check

   .DEFAULT_GOAL := help

   help: ## Show available targets
   	@grep -E '^[a-zA-Z_-]+:.*?## .*$$' $(MAKEFILE_LIST) | awk 'BEGIN {FS = ":.*?## "}; {printf "\033[36m%-15s\033[0m %s\n", $$1, $$2}'

   dev: ## Start development environment with hot reload
   	docker compose up --build

   start: ## Start production-like environment
   	docker compose -f docker-compose.prod.yml up --build

   build: ## Build production images
   	docker compose -f docker-compose.prod.yml build

   test: ## Run all tests
   	docker compose run --rm client bunx vitest run
   	docker compose run --rm server bunx vitest run

   lint: ## Run linter
   	docker compose run --rm client bunx eslint .

   type-check: ## Run TypeScript type checking
   	docker compose run --rm client bunx vue-tsc --noEmit

   clean: ## Clean up containers, volumes, and images
   	docker compose down -v --rmi local
   	docker compose -f docker-compose.prod.yml down -v --rmi local
   ```

   Important Makefile notes:
   - Use TABS not spaces for indentation (Makefile requirement)
   - Use `docker compose` (v2 syntax, not `docker-compose`)
   - help target uses self-documenting pattern with ## comments
   - test target runs tests inside containers for environment consistency
