  <name>GameEngine.swapCards()</name>
  <files>packages/server/src/game/GameEngine.ts, packages/server/src/__tests__/game-engine.test.ts</files>
  <behavior>
GameEngine.swapCards(state: GameState, playerId: string, handIndex: number, faceUpIndex: number) returns OperationResult<GameState>

Uses the same OperationResult pattern from Room.ts:
```
type OperationResult<T = void> =
  | { success: true; data?: T }
  | { success: false; error: string; code: string };
```

Define this type locally in GameEngine.ts (or import ErrorCode from shared if available).

Test cases (input -> expected output):
1. Valid swap: state.phase='swapping', valid player, handIndex=0, faceUpIndex=1
   -> success: true, data has hand[0] and faceUp[1] swapped for that player
2. Wrong phase: state.phase='playing'
   -> success: false, code: 'INVALID_ACTION'
3. Wrong phase: state.phase='transitioning'
   -> success: false, code: 'INVALID_ACTION'
4. Unknown player: playerId='nonexistent'
   -> success: false, code: 'PLAYER_NOT_FOUND'
5. Invalid handIndex: -1 or >= hand.length
   -> success: false, code: 'INVALID_ACTION'
6. Invalid faceUpIndex: -1 or >= faceUp.length
   -> success: false, code: 'INVALID_ACTION'
7. Swap preserves other players' cards (only targeted player changes)
8. Multiple sequential swaps work correctly
9. Swapping same indices swaps correctly (effectively a self-swap is valid)
  </behavior>
  <implementation>
Static method on GameEngine class. Validates phase === 'swapping', finds player by playerId, validates indices against actual array lengths (not hardcoded 0-2, in case of future changes), then performs the swap. Returns new GameState with immutable update pattern: spread player, swap values with destructuring assignment, map players array replacing the target player.

Note: Do NOT import from shared schemas — only use existing types (GameState, Card, PlayerGameState). The OperationResult type should be defined locally in GameEngine.ts to avoid coupling to the Room module's definition. Use code: string (not ErrorCode type) to avoid needing the shared package's updated error codes from Plan 01.
  </implementation>
</feature>
